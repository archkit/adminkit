# 8 つの骨格

adminkit は 36 個の部品を持つが、その多くは **8 つの骨格の組み合わせ**で説明できる。
この文書はその対応表と、部品を増やすかどうかを決めるときの規範を置く。

## 規範

**部品を増やす前に、この 8 つの組み合わせで説明できないかを確認する。**

- 説明できるなら、既存部品のバリアント（`&.xxx`）として足す
- 説明できないなら、それは新しい骨格なので、新設する前に本当に必要かを疑う
- **骨格を増やすことは、部品を増やすより高くつく**——骨格は全部品の読み方を変える

判断に迷ったら、次を順に確認する。

1. 見た目が違うだけで、情報の並び（先頭マーク / 主・副 / 数値 / 末尾）は同じではないか
2. 状態の強度（粒 → 札 → 面 → 帯）が違うだけではないか
3. 手前に出るもの（オーバーレイ族）の、位置と幅が違うだけではないか
4. 中身が無いときの表示（空 / 読み込み中 / 失敗）の 1 状態ではないか

## 骨格と部品の対応

| # | 骨格 | 何を表すか | adminkit の部品 |
|---|---|---|---|
| P1 | Row（情報行） | 1 項目を 4 スロットで並べる | `c-list.rows` / `c-table` の行 / `c-dl` |
| P2 | Meter（量の帯） | 量・構成比 | `c-meter`（内訳） / `c-progress`（単一の進捗） |
| P3 | Status（状態） | 状態を強度別に | `c-dot`（粒） / `c-badge`・`c-tag`（札） / 行の `.danger`（面） / `c-banner`・`c-alert`（帯） |
| P4 | Panel（カードの骨格） | 1 カード＝1 つの問いへの答え | `c-card` / `c-stats` |
| P5 | TimeStrip（時間の帯） | 時間 × 状態 × 量 | `c-strip` |
| P6 | Overlay（手前に出るもの） | 影を使ってよい唯一の族 | `c-dropdown` / `c-modal` / `c-drawer` / `c-palette` / `c-toast` / `c-tooltip` |
| P7 | FieldShell（入力の枠） | 枠・高さ・焦点・エラーを 1 定義に集約し、中身だけ差し替える | `c-fields` / `c-search` / `c-upload` / `c-segment` / `c-toggle-group` |
| P8 | AbsenceState（中身がないとき） | 空 / 読み込み中 / 失敗を同じ寸法で | `c-empty-state` / `c-loading-state` / `c-skeleton` / `c-spinner` |

## 各骨格の要点

### P1 Row — 情報行

先頭マーク（`.lead`）／主・副テキスト（`.body` > `.title` / `.sub`）／数値（`.value`）／
末尾（`.trail`）の 4 スロット。密度は行の高さだけで切り替える（`.compact`）。

置き換わるもの：メンバー一覧・接続の状態・ランキング・最近見た項目・ファイル行・履歴

### P2 Meter — 量の帯

`c-meter` は内訳（区分が複数）、`c-progress` は単一の進捗（native `<progress>`）。
色は必ず意味に対応させる。慣例として 90% 超で `warning`、100% で `danger` に切り替える。

### P3 Status — 状態の 4 段階

同じ状態を**強度だけ**変えて表す。1 画面で 2 段階までに抑える。

| 段階 | 部品 | 使いどころ |
|---|---|---|
| 粒 | `c-dot` | 一覧の中で状態を添えるだけ |
| 札 | `c-badge` / `c-tag` | 状態そのものが読む対象のとき |
| 面 | `c-list.rows > li.danger` / `tr[aria-selected]` | 行ごと注意を引く |
| 帯 | `c-banner` / `c-alert` | 操作を伴う告知（行動ボタンを必ず 1 つ） |

バリアントは全段階共通で `success` / `warning` / `danger`。

### P4 Panel — カードの骨格

ラベル（小）→ 主値または本体 → 図 → 脚注。**1 カード＝1 つの問いに答える**。
カード内の見出しレベルは固定ではなく、アウトライン上の位置で決まる（→ guide.md「セクショニングとアウトライン」）。

### P5 TimeStrip — 時間の帯

等間隔のセル列＝時間、色＝状態、高さ＝量。粒度（20 分 / 1 日 / 1 週）が変わっても読み方は同じ。

置き換わるもの：稼働状況・実行の内訳・週間予定・アクセスの推移

### P6 Overlay — 手前に出るもの

**影を使ってよい唯一の族。**それ以外の境界は線で引く。

| 部品 | 起点 | 幅 |
|---|---|---|
| `c-dropdown` | 起動要素の直下 | `10rem` 〜 |
| `c-modal` | 画面中央 | `32rem`（`.wide` で `48rem`） |
| `c-palette` | 上から `15vh` | `35rem` |
| `c-drawer` | 右端に固定 | `25rem` |
| `c-toast` | 右下に積む | — |
| `c-tooltip` | 対象の近傍 | — |

`dialog` を使う 3 部品（modal / drawer / palette）は、背景を押しても `esc` でも閉じる。

### P7 FieldShell — 入力の枠

枠・高さ・焦点の見せ方・エラーは `c-fields` に集約し、**中身だけ差し替える**。
検索（`c-search`）・アップロード（`c-upload`）・排他選択（`c-segment` / `c-toggle-group`）は
その中身違いとして扱う。

### P8 AbsenceState — 中身がないとき

空・読み込み中・失敗を、**同じ寸法**で置き換えられる 1 つの族として扱う。
枠の寸法を状態で変えないことが、レイアウトの揺れを止める。

## 既存部品の再定義

見た目が違って見える部品も、骨格の組み合わせで書ける。

| 部品 | 構成 |
|---|---|
| テーブル | Row（`.compact`）× n ＋ 見出し行 ＋ Status（粒 / 面）＋ 空・読み込みは AbsenceState |
| 使用量ウィジェット | Panel ＋ Meter × 3 ＋ 脚注の導線 |
| ランキング | Panel ＋ Row（`.compact` ＋ Meter `.inline`） |
| 稼働状況 | Panel ＋ TimeStrip ＋ Status の色規則 |
| アクティビティ / 履歴 | Row（`.lead` ＝主体のアイコン）＋ 時刻を `.trail` に |
| 検索・タグ入力 | FieldShell ＋ 中身の差し替えのみ |
| メニュー・ダイアログ・パレット | Overlay の派生（起点と幅だけが違う） |
| 選択 ＋ 一括操作 | Row（`.selected`）＋ 画面下端に固定した `c-action-bar` |
